# Launch kit

## Core message

> I built PulseRN because debugging one React Native bug meant switching between DevTools,
> Xcode/logcat, Redux tools, and temporary console logs. PulseRN correlates those events on one local
> timeline and keeps the history searchable.

## 90-second demo storyboard

1. Open the example Checkout screen and submit a request that returns HTTP 500.
2. Show the failed Network event and its response.
3. Follow the correlation to the Redux action and Checkout navigation event.
4. Open Native Logs and show the connected process error.
5. Open MCP and ask a configured client to summarize the failure and evidence.
6. End on `npx @maahibhama/pulsern` and the five-minute quick-start link.

## Short clips

- **One bug, one timeline:** navigation → Redux → request → error in 20 seconds.
- **Native logs:** the same app-process message in iOS Simulator and Android Emulator.
- **MCP context:** list a session, diagnose it, and open the supporting events.

## Seven-day sequence

1. GitHub release, website article, LinkedIn/X demo.
2. Feedback-oriented r/reactnative and r/expo posts after checking current rules.
3. Dev.to/Hashnode technical correlation walkthrough.
4. Participate in Reactiflux, Expo, and Infinite Red communities before sharing.
5. Show HN focused on architecture, privacy, and lessons learned.
6. Native Weekly and React Native newsletter submissions.
7. Transparent results post: usage, bugs, fixes, and next priorities.

Use distinct UTM values: `utm_source`, `utm_medium=community`, `utm_campaign=launch`, and a
channel-specific `utm_content`. Never buy stars, mass-message developers, reuse spammy copy, or
describe PulseRN as official React Native tooling.

## Weekly scorecard

Record CLI/desktop downloads, SDK downloads, first connections, weekly active opt-ins, time to first
event, GitHub stars, discussions, issues, interviews, contributors, and merged community PRs. Stop a
channel after three attempts without a useful conversation or activation.
